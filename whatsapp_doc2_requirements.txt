1. Objective and Scope
Build a WhatsApp management module for an online store, based on the attached reference image. The module must manage WhatsApp contacts and customer segments, track engagement, configure the WhatsApp Business API connection, manage phone numbers and webhooks, configure message behavior, monitor message/error logs, and display usage limits and billing information. All controls must be connected to real backend services and persisted settings; do not implement static mock values as production behavior.

23. Data, Security, Consent, and Permissions
Use role-based access control for contacts, phone numbers, API credentials, templates, segments, message logs, billing data, and settings.
Protect access tokens and verification secrets; never expose full secrets in ordinary page responses or logs.
Enforce marketing opt-in/opt-out status. Unsubscribed contacts must be excluded from marketing campaigns unless a legally permitted and policy-compliant message category applies.
Provide a reliable unsubscribe/opt-out update path and ensure changes propagate to campaign targeting promptly.
Normalize phone numbers to international format and handle duplicates using a documented deduplication policy.
Protect personally identifiable information and restrict exports to authorized roles.
Validate all input on the server, sanitize text fields, and audit sensitive configuration changes.
Use idempotency/deduplication for message sends and webhook processing to prevent duplicate messages or records.
24. Suggested Data Model
Integrate with existing application tables/services. If missing, model at least: contacts, contact identifiers and consent history, tags, segments and segment rules, contact-segment membership, customer/order aggregates, WhatsApp Business Account configuration, phone numbers, API credentials/secrets, webhook configuration and event subscriptions, message settings, message records, provider status events, error logs, usage/billing counters, team roles/permissions, and audit logs.
Keep contact metrics, segment counts, charts, revenue rankings, message limits, phone-number status, and logs derived from real source data. Define timezone, date-range semantics, revenue calculation, contact deduplication, and status taxonomy consistently.
25. Acceptance Criteria
Contacts &amp; Segments shows the five contact metrics, tabs, search/filter controls, contacts table, contact detail panel, segment cards, status chart, and revenue ranking.
Search and filters work together and update counts, rows, and pagination correctly.
Selecting a contact loads the correct details. Editing notes/tags/segments saves and reloads correctly.
Create/edit/delete segment operations work, and segment membership/counts follow the configured rules.
Charts and revenue rankings use real data and clearly defined date ranges.
API Configuration reports actual connection status and Test Connection performs a real test.
Phone number, business profile, webhook, and message settings can be managed by authorized users.
Webhook verification, event subscriptions, retries, and error handling work correctly.
Message Logs and Error Logs show real records with accurate timestamps, statuses, and error mappings.
Usage limits and billing renewal/reset dates reflect actual account configuration.
Opt-out contacts are excluded from marketing sends, secrets are protected, and access permissions are enforced.
