
Souq Marketing Channels PerformanceDeveloper Implementation Requirements


Document purpose: Specify how to implement the Marketing Channels Performance analytics page in the Souq merchant dashboard, including channel tracking, metrics, charts, data architecture, integrations, and acceptance criteria.
1. Objective and Scope
Build a working analytics dashboard that reports traffic, cart activity, completed orders, conversion, and attributed revenue by marketing channel. All production values must come from actual tracked events, order records, or authorized integrations. Never use hard-coded or fabricated metrics.
The page must support store-level data isolation, date filtering, channel search and sorting, export, charts, and integration synchronization status.

5. Metric Definitions
Metric
Definition

Completed Orders
Count of orders meeting the agreed completed/paid status rules within the selected period.

Revenue
Sum of eligible order revenue under the documented reporting policy, with cancellations/refunds handled consistently.

Total Visits
Count of sessions or visitors; choose one definition and label it accurately.

Conversion Rate
Attributed completed orders divided by eligible visits, multiplied by 100. Document the attribution and counting rules.

Add to Cart
Count of add-to-cart events or distinct sessions with an add-to-cart event; select one definition and use it consistently.

AOV
Eligible attributed revenue divided by eligible completed orders. Show “—” when the denominator is zero.

Revenue Share
Channel attributed revenue divided by total attributed revenue across the same scope, multiplied by 100.

Growth
((Current-period value - previous-period value) / previous-period value) × 100. If the previous value is zero, show “New” or “—” rather than an infinite percentage.

All dashboard components must use the same metric definitions and filters. If visits are zero, avoid division by zero and display the agreed empty-state value.

7. Backend API Expectations
Implement endpoints consistent with the project’s API conventions. Example endpoint shapes:
GET /api/analytics/marketing/summary?from=YYYY-MM-DD&amp;to=YYYY-MM-DD
GET /api/analytics/marketing/channels?from=YYYY-MM-DD&amp;to=YYYY-MM-DD&amp;sort=revenue
GET /api/analytics/marketing/trends?from=YYYY-MM-DD&amp;to=YYYY-MM-DD&amp;interval=day
GET /api/analytics/marketing/integrations
POST /api/analytics/marketing/export
These are illustrative routes, not a requirement to override existing API conventions. Validate date ranges and store access on the server, return consistent response schemas, and paginate large datasets.
8. External Integrations and Sync
UTM/event/order tracking can provide attributed store traffic and sales without a direct ad-platform API. Ad spend, impressions, clicks, and campaign-level performance require authorized platform integrations and the appropriate permissions.
Provide a Connect / Disconnect flow for each supported provider where an integration is implemented.
Store access tokens and secrets securely on the server; never expose them to browser code.
Use scheduled/background sync with retry handling, rate-limit handling, and clear error states.
Show last successful sync time and status per provider.
Distinguish Not Connected, Connected, Syncing, Error, and No Data states.
Do not assume every listed channel offers the same metrics or API capabilities.
Document data freshness and any provider-specific attribution limitations.
9. Security, Privacy, and Reliability
Enforce store/tenant isolation on every analytics query and export.
Apply role-based access controls to analytics and integration settings.
Respect applicable consent, cookie, privacy, and platform API requirements.
Minimize personal data in tracking events and apply retention rules.
Prevent duplicate event and order counting through idempotency and unique identifiers.
Use clear loading, empty, partial-data, and error states.
Log sync failures without exposing secrets or sensitive customer data.
Make calculations timezone-aware and define the store reporting timezone.
10. Acceptance Criteria
Changing the date range updates all KPI cards, the table, charts, and exports.
Every displayed production metric is sourced from tracked events, order records, or an authorized provider integration.
Table totals reconcile with the same eligible source records and metric definitions used by the summary cards.
Revenue share totals approximately 100% when all attributed revenue is included, allowing for rounding.
Zero denominators and zero previous-period values are handled without invalid calculations.
The same order or event cannot be counted twice.
Unconnected providers are clearly marked; unavailable data is not represented as actual zero performance.
Search, sorting, column visibility, and export work correctly.
Sync status and last successful sync time are displayed accurately.
Store data isolation and permissions are verified by tests.
Charts have readable labels, legends, tooltips, and empty states.
11. Recommended Implementation Phases
Phase 1 — First-party analytics
Implement UTM capture, session/event tracking, order attribution, metric definitions, and reliable summary APIs.
Phase 2 — Dashboard UI
Build KPI cards, date controls, channel table, charts, search, sorting, and export.
Phase 3 — Ad platform integrations
Add authorized provider connections and sync for ad spend, impressions, clicks, and campaign metrics where supported.
Phase 4 — QA and optimization
Validate calculations, privacy/consent behavior, tenant isolation, sync recovery, performance, and reporting consistency.
12. Important Implementation Notes
Do not treat the visual reference as a source of real data; it defines layout and intended functionality only.
Use the existing Souq order, store, authentication, and design systems wherever possible.
Clearly distinguish attributed revenue from total store revenue and ad-platform-reported conversions.
Document the attribution model, reporting timezone, revenue/refund policy, and exact definitions of visits and add-to-cart before launch.
If an integration is not implemented or authorized, show its status honestly and avoid fabricated metrics.
