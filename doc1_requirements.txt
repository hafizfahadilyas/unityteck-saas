
WHATSAPP MESSAGE CENTER
Message Management, Composer &amp; Templates — Developer Requirements
Complete English functional specification based on the supplied reference image
1. Objective and Scope
Implement the WhatsApp Message Center for the store. The interface must allow staff to monitor message performance and delivery, browse and filter message records, send messages, compose personalized messages, manage approved WhatsApp templates, attach media, preview messages on mobile/web, and insert dynamic template variables. Connect every operational control to real backend services and the WhatsApp Business API integration. Values shown in the screenshot are illustrative examples, not production defaults.
2. Main Views in the Reference
View A — WhatsApp Message Center: connection status, daily usage, message metrics, message-category tabs, filters, message table, per-message actions, and pagination.
View B — Compose Message &amp; Templates: tabs for Compose Message, Message Templates, and Media Library; approved-template list; message composer; recipient/order selection; media attachment; preview; template variables; and send/save actions.
Use the same dark navy sidebar, white/light content background, blue/teal/green accents, compact data cards, and rounded panels shown in the screenshot.

12. Message Row Actions
Provide a per-row ellipsis menu.
Supported actions may include view details/conversation, view delivery events, retry/resend failed messages where policy permits, and open the associated customer/order.
Do not resend automatically without checking WhatsApp policy, message-window rules, template requirements, and duplicate-send safeguards.
Actions must be permission-controlled and show success/failure feedback.

16. Message Content Editor
Provide a rich-text/message editor with the formatting controls shown: bold, italic, lists, link, emoji, and Variables dropdown, where supported by WhatsApp message/template capabilities.
Support template placeholders such as {{customer_name}}, {{order_id}}, {{tracking_link}}, and {{store_name}}.
Show a character counter; the screenshot example shows 210/1000. Enforce the actual maximum for the selected message type and provider API.
Allow editing only in ways permitted for the selected template. Approved WhatsApp templates may have fixed structure and variable slots; do not allow unauthorized edits that invalidate provider-approved templates.
Validate required variables before preview or send. Highlight missing values and prevent accidental sending with unresolved placeholders.
Sanitize content and validate links and supported formatting.

19. Message Preview
Display a live preview panel with WhatsApp (Mobile) and WhatsApp (Web) tabs.
Mobile preview should resemble a WhatsApp conversation, showing recipient name/status, date separator, rendered message body, links, variables, media, and timestamp/check marks where appropriate.
Web preview should represent the message in the supported WhatsApp Web layout.
Preview must update as the user changes template, recipient, variables, message content, or media.
Preview data must be clearly distinguished from an actual sent message. Do not create real message records or send API requests merely by previewing.
20. Composer Actions
Action
Required Behavior

Save as Draft
Save the current composition, selected template, recipient/order context, variables, and media references as a draft without sending.

Send Test Message
Send a test to an explicitly selected test recipient or configured test destination, with confirmation and a clear test indicator.

Send Message
Validate all fields and policy requirements, show a final confirmation where appropriate, then send through the connected WhatsApp service and report the resulting status.

Prevent double-click duplicate sends. Record message IDs/provider responses and handle queued, sent, delivered, read, and failed states as separate lifecycle states where supported.
21. Template Management Requirements
Support creating, editing, viewing, submitting, and managing templates according to provider capabilities.
Display template name, category, language, status, content, variable definitions, and approval/rejection information where available.
Approved templates must follow the provider-approved content structure. Changes requiring reapproval must be handled as a new version or submission according to provider rules.
Support template search and filtering by category/status.
Template deletion/archive must be permission-controlled and must not break historical message logs.
22. Message Delivery, Policy, and Error Handling
Integrate message sending and status updates with the configured WhatsApp Business API provider.
Respect WhatsApp conversation-window and template rules, recipient consent, rate limits, and provider restrictions.
Handle failed sends with mapped provider error codes and readable explanations.
Retry only where appropriate, with bounded backoff and idempotency safeguards.
Persist timestamps, sender/agent, recipient, message type, template, order/customer association, provider message ID, delivery events, and error details.
Never expose API secrets in the UI, logs, or client-side code.
23. Security, Permissions, and Privacy
Apply role-based access to viewing messages, composing/sending, sending tests, managing templates, accessing media, and viewing customer/order information.
Restrict custom-number sending to authorized users and validate number format and eligibility.
Protect customer phone numbers, message content, order details, and media references.
Log sensitive actions such as sending, template changes, and retries in an audit trail where supported.
Prevent unauthorized exports or disclosure of customer information.
24. Suggested Data Model
Integrate with existing application structures. If missing, provide entities for messages, recipients, message categories/types, delivery/status events, customer/order associations, agents, approved templates and versions, template variables, drafts, media attachments, provider message IDs, send attempts, error records, and usage counters.
Ensure message metrics, category counts, daily usage, table filters, pagination, preview content, and delivery states are calculated from real data and remain synchronized with provider callbacks.
25. Acceptance Criteria
Message Center displays connection status, daily usage, total/delivered/read/failed metrics, message-category tabs, filters, table, actions, and pagination.
Search, date range, message type, status, template, and agent filters work together.
Message rows show correct timestamps, customer, phone, order, content, type, status, and agent.
Compose Message supports customer/order/custom-number recipients, template selection, variable insertion, media attachment, and live preview.
Template Variables can be copied and resolve correctly from customer/order/store data.
Save as Draft persists a draft without sending; Send Test Message sends only to the intended test destination; Send Message sends through the configured provider.
Approved Templates supports search, category/status filters, template creation, and accurate provider approval states.
Message lifecycle updates and failures are reflected accurately in metrics and logs.
The UI is responsive, respects permissions, protects customer data, and prevents duplicate sends.
